## 2. 模式与入口隔离（强制）

现已增加独立程序 `xtrader_replay`、`xtrader_paper`、`xtrader_ctp_sim` 和
`xtrader_live`。它们目前仅提供帮助，其余调用均失败，不读取配置或连接柜台；
**尚不是可用交易入口**。具体业务和可信绑定仍需按下表实现。

| 入口 | 数据来源与执行通道 | 必须拒绝的行为 |
|---|---|---|
| 纯模拟/历史回放 | 本地历史或显式生成的模拟数据 + 本地撮合账户 | 创建 CTP 交易连接、加载实盘交易凭据 |
| 实时本地模拟 | 实时行情 + 本地撮合账户；行情认证与交易权限分离 | 创建实盘交易通道、向柜台发送委托/撤单 |
| CTP 柜台模拟盘 | 经确认的模拟行情/交易前置 + 模拟账户 | 使用实盘交易前置或实盘账户 |
| 实盘 | 独立实盘启动入口 + 经批准的实盘配置与账户 | 从模拟入口切换进入、隐式启用实盘、未就绪即交易 |

独立入口不是共用 Live 菜单中的选项或仅靠一个 `--mode` 参数切换。可以复用内部模块，但模拟入口不得通过换配置或参数获得实盘交易能力；普通 CLI 不直接启动实盘，不在运行中切换交易环境。

必须同步实现：

- 配置、凭据、CTP flow、Redis 写入命名空间、交易日志、订单编号状态、持仓及恢复快照按环境/账户隔离；历史共享只读数据须显式声明。
- 实盘默认关闭；启动前展示醒目的实盘标识、账户脱敏信息、目标前置和策略/合约范围，要求独立显式授权与确认；无人值守使用可审计的专用授权，不绕过隔离。
- 不能仅信任 `account_env=simu`、目录名或端口。按受控的环境/账户/前置绑定规则校验；无法确认、配置缺项或冲突时拒绝启动交易。
- 纯模拟不初始化交易 API；实时本地模拟若需行情认证，仅允许行情权限。日志、证据和命令行不得暴露凭据。
- 提供交叉误配置负向测试：模拟入口 + 实盘配置、模拟账户 + 实盘前置、缺少授权、环境未知、运行时切换，均须在交易连接/发单前失败。
- 旧 CLI 的 `ENCv1` 使用自制 XOR/FNV 派生，不可作为安全凭据存储的依据；CLI 已移除该创建及解密流程，但不会修改现有配置。真实凭据接入前须采用并审查合适的凭据管理及迁移方案。

## 3. 六阶段现状与修订责任

| 阶段 | 原职责 | 本轮确认的现状与修订 |
|---|---|---|
| 第一阶段 | 模块/类型映射、交易语义基线 | 补充四种模式、实际策略与外部消费者清单，将“完整替换”转成逐项可验收矩阵 |
| 第二阶段 | 运行时骨架、构建与启动 | Debug/Release 构建及帮助检查通过；正式运行组装、独立入口与环境隔离仍待开发 |
| 第三阶段 | CTP 行情/交易桥接 | 有 API/SPI 和队列代码；订阅、回报处理、启动同步、恢复及线程所有权仍需闭环 |
| 第四阶段 | 策略生命周期、分发、回测 | 有模块和最小测试；初始化存在 ASan 缺陷，完整撮合、回报、资金及回放语义未闭环 |
| 第五阶段 | 数据、Redis、只读 Web、多环境链路 | 有导入及元信息/接口代码；实时录制、实际生产调用、兼容性与运行接线仍需补齐 |
| 第六阶段 | 性能、长稳、一致性、灰度 | 指标/门禁、离线回归与短时探针通过；不代表真实交易链路或最终替换验收通过 |

原计划第六阶段“仅提交验证文档、不新增代码”的约束修订为：允许补充验收所需指标、门禁、对照和故障注入工具；业务功能缺口仍归属第二至第五阶段，不以第六阶段工具替代业务实现。

## 5. 实施顺序与放行门禁

1. **先收口基线与安全边界：**R1-01/R1-02、R2-01；修复 R4-01，并明确所有配置组合的拒绝规则。
2. **建立无真实交易的完整闭环：**完成运行时、策略、本地撮合、账务、回放、风控和报告；使用离线桩/固定数据覆盖 CTP 回报与错误场景。
3. **接入实时本地模拟和柜台模拟盘：**在入口隔离及目标环境校验通过后，经用户授权连接对应服务；补齐查询、回报、录制、重连和恢复。
4. **完成替换范围与运行验收：**逐项迁移实际策略和外部数据依赖，完成两环境长稳、新旧对照、恢复与回退演练。
5. **最后开放实盘：**所有 P0 项关闭、替换范围内 P1 项验收通过并经人工签核后，才可单独授权有限范围的实盘灰度。本文不是连接实盘、下单、切流或停止旧系统的授权。

第六阶段的实盘一致性检查应先用记录回放、旁路只读观测和模拟盘完成可执行部分；需要真实委托的验证必须另行批准范围、账户、时段、额度及停止条件。禁止为获得测试证据让新旧系统同时对同一交易范围发单。

**B3 内部回放接口的当前边界：**`backtest_config::data_mode` 默认读取历史数据；
仅显式设置 `embedded_demo` 才使用内置样例。历史 bar 采用严格 CSV 表头
`date,open,high,low,close,volume,open_interest`，允许其后包含导入器的
`money,source_symbol` 等列，但每行列数须与表头一致；缺失、歧义或损坏的数据直接报错。
`start_date`/`end_date` 是包含端点的**日历日期**过滤，不是交易日过滤；
多合约按 CSV 给出的本地日期与时间排序，相同时间按合约和文件行顺序确定次序，
同优先级策略按策略 ID 顺序接收，尚未验证数据时区、bar 开始/结束时间含义和交易所日历，
不能据此认定回测结果可信。当前仅用固定的 09:00–11:30、13:30–15:00 和
21:00–02:30 时段做初步检查，时段外数据会报错；这不是交易所或合约的真实日历。
策略须通过 `subscribe_bar_data` 订阅并实现 `on_bar`；历史 bar 不再冒充 Tick，
也不由收盘价乘成交量虚构成交额。回放前须启动 driver 与 event bus，且必须有运行中的
订阅策略；回调完成前不报告回放完成，停止时等待当前回调并中断剩余事件，失败后须创建新的
driver。原先缺少委托簿和账务的 `execution_simulator` 已明确禁用，调用或尝试接入时会报错。
回调超时和强制取消机制尚未完成；上述仅为内部数据投递能力，不是可下单的纯模拟入口或
完整的交易回测。

**B3 内部离线撮合核心的当前边界：**`simulated_order_book` 独立于柜台和回放驱动，
通过 `offline_simulated_execution` 接入独立离线账务；内部适配器已连接部分策略回调和历史 bar
导出数据，但尚未接入原有 `backtest_driver::run()` 或正式入口。
只支持显式限价单；按本地委托价格、提交顺序竞争
每次事件中对应方向的流动性，支持部分成交与按运行编号、策略归属撤单。Tick 模式只使用
后续事件的最佳买卖报价及各自盘口量；缺失报价或盘口量、交叉报价、无效数字以及重复或
倒退的事件序号均报错。买卖盘口量可显式为零，不能从成交量推测盘口量。

Bar 模式只接收后续 bar 的开盘价，要求创建委托簿时显式提供每根 bar、每个买卖方向的
固定流动性上限，不读取该 bar 的最高价、最低价、收盘价或最终成交量。这个上限是待确认的
近似模型参数，不是交易所成交量；用户尚未确认具体取值，不提供默认值。所有本地成交均标记
为近似，且记录来源为最佳盘口快照或 bar 开盘价；Tick 撮合也没有真实队列位置、市场冲击、
逐档盘口或跨快照流动性去重，不能视为柜台实际成交。

事件序号必须由调用方按真实输入顺序稳定分配；若将重复源数据伪装成新序号，委托簿无法识别。
独立 `offline_bar_timeline` 要求每条 bar 显式提供开始或结束时间语义、持续时间、交易日和统一
时间域标识，并拒绝同合约时间重叠、混用时间域或非法 OHLC。相同时间先处理所有已完成 bar，
再处理新 bar 开盘；开盘通知不包含该 bar 未来的高低收及最终成交量。这个顺序假定策略能在
收盘与下一开盘间无延迟决策，仅是显式离线近似；时间域标识和交易日均由调用方声明，不证明
其与真实时区或交易所日历一致。真实 CSV 时间语义、时区、交易日和数据去重仍须在接线前验证。

独立 `offline_bar_replay` 在运行前校验全部 bar 的单交易日标签和价格归一化，按时间线执行
模拟撮合，并向内部回调提供委托结果、账户快照及已完成 bar；失败或停止后不能继续下单。
当前异步回调及停止处理尚未验证，也没有接入报告或正式纯模拟入口。
回放结束不自动平仓或撤单，未完成委托及持仓须显式检查；回调超时与强制取消尚未实现。

新增 `offline_bar_strategy_replay` 仅用于内部单策略、单合约适配：使用现有策略生命周期，
在完整 bar 回调后排空委托回报，在下一个开盘撮合并顺序派发订单和成交回报。成交回报标记
为近似 bar 成交，手续费由明确提供的货币单位比例转换为策略接口的 `double`；整数账本仍是
权威的离线计算结果。时间文本由调用方显式转换，通用平仓顺序、成交价格上界和通知上限也
必须配置；适配器不证明这些配置符合真实交易所规则。由于尚无盯市/权益模型，
策略账户查询明确报错，不提供虚假的完整账户视图；策略停止回调期间不允许新增或撤销委托。
适配器要求价格最小变动、合约乘数、货币单位比例和每手 tick 价值相互一致，最多容许一个
浮点 ULP 的计算差异；尚不支持额外的汇率换算。同一行情事件内所有成交先整体结算，再按
确定顺序分发回报，策略回调查询到账的是该事件提交后的账户状态。
适配器及其新回归均未编译、运行或接入正式入口，不代表 B3 已完成。

`backtest_driver::export_offline_bars` 可将已加载历史 bar 导出给离线适配器；调用方须显式
提供时间戳属于开盘还是收盘、固定 bar 时长、统一时间域标识及交易日解析函数。解析函数负责
结合真实交易所日历校验源数据和 bar 区间，不能简单地把日历日当交易日；源码尚无权威日历。
CSV 的本地日历时间仍以未附时区的数值编码，适配器的时间文本转换也由调用方提供。此导出链路
和新增的 CSV→策略→撮合回归尚未运行，不能视为完整纯模拟入口或可信历史回测。
本地订单/成交编号由调用方提供的运行编号及递增序号组成，运行编号的唯一分配和持久化尚未实现；
策略名称和运行编号只是命名空间，不是身份认证。权威手续费/保证金规则、跨日开仓成本
管理、滑点及结果持久化尚未完成。
旧 `execution_simulator` 和四个正式入口继续禁用。

`offline_simulated_execution` 当前只接受一个显式策略、一个账户和单交易日空仓，订单及行情
价格由调用方提供整数 tick，手续费、保证金、FIFO 成本规则和价格上界均需显式配置。
一个行情事件内所有撮合和账务变更一起暂存提交；任一成交无法结算时，整次事件不提交并
停止继续下单。价格归一化允许调用方显式选择严格匹配或最多一个浮点 ULP 的无歧义调整，
并报告是否调整；多于一个 ULP、非正、非有限或歧义价格直接拒绝。该工具尚未接入历史
数据加载流程，跨策略持仓归属和策略事件排空也仍需实现；这只是独立离线组件，不能视为
完整回放或可使用的交易程序。

**B2 离线账务基础的当前边界：**资金账本使用调用方明确指定的整数货币单位及保证金、
手续费和平仓盈亏，不推断交易所或账户规则；初始账户仅支持无持仓、无未完成委托的状态。
成交与终态报告支持去重、部分成交、撤单释放及迟到成交；与持仓账本的协调通过复制全部
内存状态后再交换提交，单次操作为 O(n)，尚不具备生产性能、持久化或重启恢复能力。
基础协调器不能独立核实平仓释放保证金是否对应实际持仓批次；上层离线 FIFO 账户会记录
本运行内的开仓批次并据此计算释放金额。调用方提供的经济数值和账户范围不能作为柜台认证
或实盘授权。

`offline_futures_economics` 仅提供一个可显式配置的离线近似模型：按整数价格 tick 和每手 tick
价值计算名义金额，多空保证金比例及开仓、普通平仓、平今、平昨手续费分别提供，金额比例的
取整方式必须显式指定；先按每手取整再乘成交手数。预留资金需要调用方提供成交价格上界，
超过上界的成交会被拒绝。计算器本身只计算调用方指定的**单一开仓批次**；上层
`offline_futures_account` 要求显式选择 FIFO、绑定账户货币单位和合约参数，并按成交先后
为当日开仓批次分配成本及保证金。成交、持仓、资金与批次修改一起暂存提交；部分成交、并发
平仓、撤单后的迟到成交和重复回报均有离线回归。

此账户只支持单交易日从空仓开始，不支持既有持仓导入、跨日盯市或日结；FIFO 仅是可选模拟
模型，尚未确定与目标账户规则一致。价格最小变动单位和每手 tick 货币价值均由调用方显式
提供，其相互关系和真实数据的价格归一化契约尚未验证；计算结果不能代表交易所或柜台规则。
该账户仅通过上述独立离线协调器接入撮合器，未接入回放驱动或正式入口；
复制全量状态的开销也尚不适合生产。

### 7.6 B1 事件与账务契约草案

以下是后续实现的约束，不代表当前代码已符合，CTP 标识的唯一性范围及交易所规则仍须验证：

1. 账户状态按可信环境、券商及投资者隔离；持仓再按交易日、交易所/合约、投机套保、方向和今昨仓区分。缺少任一关键归属或环境不可信时，不开放委托。
2. 柜台本地委托关联至少保留账户、交易日、`FrontID`、`SessionID` 和 `OrderRef`；收到系统单号后保留交易所及 `OrderSysID` 映射。模拟撮合使用独立且可持久化的本地委托/成交编号，不伪造柜台标识。
3. 成交去重候选键包含环境、账户、交易日、交易所和 `TradeID`；缺字段不得静默记账。其实际唯一性须用柜台规范/模拟柜台回报验证，重启恢复需持久化去重状态。
4. 本地调用成功只表示请求已发送，不能视为柜台已接受。订单回报依次处理已提交、已接受、部分成交及成交/撤销/拒绝等状态；拒撤是撤单请求失败，不得把原委托标记为已撤销。乱序、重复、终态冲突和未知状态须有明确处置。
5. 报单冻结、成交扣减、撤单/拒单释放必须守恒；手续费、保证金、开平及今昨仓按照合约、交易所和账户规则计算。超可平量、缺失资金/合约参数及对账不一致时拒绝新单，而非使用零值或模拟资金冒充实盘数据。
6. 同一策略的回调不重入并保持接收顺序；停机先拒绝新事件，再排空事件总线及策略回调，最后销毁上下文。关键订单/成交回报不得静默丢弃；断线、回报缺口或恢复未完成时禁止新增委托。

CTP 账户与前置的权威绑定来源、独立凭据管理方式、目标交易所及业务策略参数仍待确认。
在这些前提及 B4/B7 安全链路完成前，不能把配置字段、目录名或端口当作环境证明。

#### B5：内部行情与本地模拟

- `market_data_pipeline` 只接受配置清单内的交易所/合约；输入必须显式携带单一时间域、

- 校验最优盘口、盘口量、最新价和持仓量；重复/倒退序号、时间倒退、日内累计量下降、
  重叠时段或缺失值明确报错。第一笔、跨交易日及数据缺口后无法可靠计算的增量使用
  `optional` 缺失值，不把累计量全部算成当前 Tick 成交量。全局序号缺口使所有合约的
  增量基线失效；不能把本地重新编号当作源数据去重。
- 分钟聚合不补造无数据分钟。跨分钟累计量增量无法精确分摊时不分摊，输出
  `observed_volume` 并标记不完整；开始中途接入、序号缺口、停止时的最后一根 bar
  也标记不完整。该严格观测格式**不能直接当作完整历史 bar 导入**；完整性只针对输入流，
  不证明上游没有漏行情。
- `paper_market_session` 组合上述管线与已有 `offline_simulated_execution`，不拥有 CTP
  交易网关。只允许 `paper` 命名空间、单策略/单账户/单交易日空仓起步，合约经济参数、
  运行编号和行情接收后最大处理延迟必须显式提供。记录 future 成功后才进行后续盘口撮合，
  成交沿用近似标记与原子账务；同一时间只处理一个 Tick，不维护无界队列。
- 异步接收参数通过 `do_with` 持有，停止排空 gate；录制失败、序号缺口、断线、跨交易日
  或录制耗时超限后停新单，没有自动恢复。只有已收到该合约行情且本地接收时间未过期才能
  下单；这不检测源端积压，真实接线还须校验源时间与本地时间。断线/录制失败时仍可尝试
  本地撤单，但账本不一致、处理进行中或停止中会拒绝。停止不自动撤单或平仓。
- 录制 sink 是必须安装、必须等待的异步接口；它必须用非阻塞 I/O，成功表示已确认写入，
  不能仅表示进入另一个队列。`market_record_format` 已提供 Tick JSON v1 和分钟 CSV v1
  编码，缺失增量写为 JSON `null`，未安装同步 hiredis 或阻塞文件写入。
  **具体 CSV 文件/Redis 传输与保留策略仍待实现**，当前不宣称已完成生产录制。
- 新增 `xtrader_market_pipeline_test.cc`，覆盖增量/跨日/缺口、格式与命名空间、
  后续盘口成交、录制失败不撮合、故障撤单及延迟 sink 停机排空；仅注册，未运行。

#### B6：恢复停单协议

`recovery_coordinator` 默认停单；每轮恢复必须使用新的连接代数，核对
`ctp_query_tracker` 中合约、资金、持仓、订单、成交五类查询全部完成且一致。
之后要求账户范围一致，认证、结算和订阅已确认，持久化序号与已应用序号相等、
快照不超前，无未决委托、持仓或资金差异；否则进入人工处置。
对账通过仍不放行，必须在显式时间窗内用同代数、同对账编号和非空授权审计引用恢复。
新的回报或状态变化须调用失效接口使旧对账结果不能继续放行，断线清除恢复授权。
新单门禁与“连接已认证且委托身份已知”的撤单条件分开，没有任何自动重发委托的接口。

**边界：**这是 owner-shard 内部协议，不是身份认证服务；授权字符串只是外部授权流程的
审计引用，不能由普通配置自行填写后当作批准。证据数字是未来持久化/对账适配器的报告，
该组件不写 WAL、不 fsync、不加载快照、不恢复账本/去重状态，也没有实际重认证/重订阅。
它尚未接入 `ctp_gateway` 或正式运行时，不能宣称断线或进程重启恢复已实现。
新增 `xtrader_recovery_coordinator_test.cc` 覆盖缺查询、未决委托、差异、旧代数、
失效/过期批准和撤单分离；尚未运行。

#### B7/B8：离线证据与逐笔对照

`tools/xtrader_acceptance.py` 是只读 Python 标准库工具，不执行外部命令、连接服务、
读取交易凭据或改变入口开关。具体操作见调试指南第 9 节。

- `template` 输出所有任务均待完成的证据清单，不生成通过证据。
- `gate` 要求 27 项 WBS、四模式验证、至少两套不同目标环境各自 8h/24h 真实业务链路、
  零订单/成交丢失、容量/恢复及资源趋势审核、已批准阈值引用、新旧对照、单写者和回退演练。
  证据须是清单目录内的非空文件且 SHA-256 匹配；缺项、阻塞或未审核项不能通过。
- `compare` 对两份按同一输入/参数导出的 JSONL 逐条精确比较，保留委托、成交、持仓与
  账户四类记录。价格为整数 tick、资金为整数单位，不通过浮点容差隐藏差异；
  不排序以掩盖事件顺序，不接受跳号、重复已结算成交、空文件、缺类或非法数据。
  夜盘可跨日历日但保持真实交易日标签；跨交易日只允许单调推进，不能回退。
- 证据库存完整只输出 `evidence_inventory_complete`，对照一致只输出 `identical`，
  两者均固定 `live_authorized=false`。文件哈希不证明报告属实；比较相等也不证明旧系统
  正确。工具不会签核业务结论或批准真实交易。
- 新增标准库用例 `tests/unit/xtrader_acceptance_test.py`，在 CMake 找到 Python3 时注册。
  覆盖空模板、完整但不授权、篡改/路径越界、缺任务/重复环境、缺数据/顺序/金额差异等；
  仅编写，未运行。
